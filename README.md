# Thallos

YOLOv8 기반 객체 인식 및 충돌 감지 파이프라인 구현

---

## 1. 프로젝트 개요

Thallos는 단일 카메라 기반 객체 인식과 충돌 위험 판단을 목표로 한 프로젝트이다.  
YOLOv8을 활용한 커스텀 객체 인식 모델을 직접 설계·학습하고, OpenCV 기반 차선 인식과 거리 추정을 결합하여 충돌 가능성을 판단하는 전체 파이프라인을 구현하였다.

또한 SBC–서버 구조에서 영상 스트리밍과 추론 결과 피드백을 소켓 통신으로 직접 구현하며, 실시간 시스템에서 발생하는 병목과 한계를 분석하는 데 초점을 두었다.

---

## 2. 시스템 구성

### 전체 파이프라인

[Camera (SBC)]
↓
JPEG 압축 + 인코딩 (Multi-thread)
↓
TCP Socket
↓
[Server]
├ YOLOv8 객체 인식 (Custom Model)
├ OpenCV 차선 인식
├ 거리 계산 및 충돌 판단
↓
추론 결과(JSON) 전송
↓
[SBC]
└ OpenCV 후처리 및 시각화

---

### 하드웨어 / 환경

- Camera: USB Camera (1200 × 800)
- SoC: Qualcomm® QRB4210
- Communication: TCP Socket
- Processing: Multi-thread

---

## 3. 객체 인식 모델 (YOLOv8)

---

### 3.1 클래스 설계 기준

- 클래스 간 시각적 특징이 유사해야 학습 안정성이 높음
- 클래스 수 증가가 성능 향상을 보장하지는 않음
- 객체를 몇 개의 클래스로 분류할지에 대한 기준 설정이 중요

---

### 3.2 클래스 구성

vehicle, big_vehicle, bike, human, animal, obstacle

- obstacle: 빨간 꼬깔콘, 공사 현장 표식 등 실제 도로 환경에서 자주 등장하는 객체만 포함
- bike: 사람을 제외한 이륜 객체만 라벨링  
  (사람과의 중복 인식 문제로 분리)

---

### 3.3 데이터 수집 및 라벨링

- 유튜브 도로 주행 영상 활용 (낮 / 밤)
- 시계열 프레임 추출
- 반대편 차량, 가드레일 포함
- 라벨링 도구: labelImg

#### 데이터 정제 기준

- 검은 옷을 입은 사람 데이터 제외  
  (그림자까지 human으로 인식되는 문제 발생)
- 중거리 차량 인식 실패  
  → 해당 거리 데이터 부족으로 판단 후 보강
- 클래스별 데이터 개수 비율 유지
- 데이터 양 증가가 성능 향상을 보장하지 않음

---

### 3.4 모델 학습

- Model: YOLOv8n
- Output: Custom Model (`best.pt`)

---

## 4. 충돌 감지 로직

---

### 4.1 고정 폴리곤 기반 충돌 감지

- 영상 상 특정 좌표 영역(Polygon)을 충돌 위험 구간으로 설정
- 객체 Bounding Box가 해당 영역에 진입 시 위험 판단

---

### 4.2 차선 인식 기반 충돌 감지

- OpenCV 기반 차선 검출
- 차선 내부 객체만 거리 계산 대상에 포함
- 일정 거리 이하 진입 시 충돌 위험으로 판단

모든 객체에 Bounding Box를 표시하지 않음  
→ 후처리 속도 저하로 FPS 감소  
→ 실시간 처리 성능 확보를 위해 시각화 최소화

---

### 4.3 거리 추정 (초점거리 기반)

f = (W_pixel × D) / W_real

- f: 초점거리
- W_pixel: 이미지 상 객체 너비 (pixel)
- W_real: 실제 객체 너비
- D: 카메라와 객체 사이의 거리

#### 한계점

- 렌즈 왜곡, 카메라 설정에 따른 오차 발생
- 촬영 거리 정확도가 결과에 직접적인 영향
- 카메라 캘리브레이션 필요

---

## 5. 통신 구조 (SBC ↔ Server)

---

### 데이터 흐름

1. SBC에서 영상 캡처
2. JPEG 압축 → 인코딩 → 서버로 전송 (멀티 스레드)
3. 서버에서 디코딩
4. YOLO 커스텀 모델로 객체 인식
5. OpenCV로 차선 인식 및 충돌 판단
6. 결과를 JSON 형태로 직렬화하여 SBC로 전송
7. SBC에서 OpenCV 후처리 및 출력

---

### 통신 구현 중 발생한 이슈

- NumPy 타입을 포함한 데이터 직렬화 실패
- 직렬화 실패 → 응답 미전송
- 클라이언트 `recv()` 무한 대기 상태 발생
- 모든 값을 Python 기본 타입으로 변환하여 해결

---

## 6. 프로젝트 소감 및 한계

---

### 전처리의 중요성

- 클래스 정의, 데이터 수집 기준, 라벨링 범위에 따라 모델 성능이 크게 달라짐
- 데이터의 양보다 품질과 분포가 더 중요함을 체감

---

### OpenCV 기반 차선 인식의 한계

- 허프 변환 방식은 곡선 차선 대응이 어려움
- 엣지 기반 방식은 그림자, 밝기 변화에 취약
- ROI 기반 접근은 오르막·내리막 환경에서 한계 발생
- 복잡한 차선 형태 반영이 어려움

---

### 실시간성 문제

- JPEG 압축 및 인코딩 과정에서 가장 큰 지연 발생
- 멀티 스레드 적용 및 압축률 조정에도 실시간성 한계 존재
- 안전과 직결되는 기능이므로 프레임 스킵은 적용하지 않음

---

## 7. 향후 개선 방향

- ROS 기반 파이프라인으로 실시간성 개선
- 딥러닝 기반 차선 인식 적용  
  (YOLO 기반 차선 인식, SCNN, ENet, LaneNet 등)
- 카메라 캘리브레이션을 통한 거리 추정 정확도 향상
- 센서 퓨전 구조로 확장 가능성 검토
